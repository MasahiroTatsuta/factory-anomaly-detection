# Factory Anomaly Detection - AI × MLOps × Web統合システム

## 🚀 Summary
本プロジェクトは、工場設備の音響異常検知を目的としたAI × MLOps × Web統合システムです。
実務における2大課題である「極度なクラス不均衡（異常比率 11.5%）」および「マシンの個体差によるノイズ変動（ドメインシフト）」に対し、厳密な完全対照実験（Control Experiment）を実施。音響特徴量のダイナミックな正規化とVision Transformer（ViT）の構造적優位性を証明し、実運用に耐えうる高性能な産業用AIシステムを構築しました。

### 成果（完全同一条件下における一騎打ち結果）
- 🟦 **Baseline CNN (ResNet18):** 総合精度 74.0% | 異常検知率 62.0% | ROC-AUC 0.906
- 🔥 **Proposed Method (ViT-Tiny):** **総合精度 97.6%** | **異常検知率 96.7%** | **ROC-AUC 0.997**
- **プロダクト実装：** 本番環境（Hugging Face Spaces）へ前処理パイプラインを完全同期し、コンテナ推論によるリアルタイム運用を実証済。

### 特徴
- **アルゴリズム：** 音響データ処理（Min-Max正規化） × Vision Transformer (ViT-Tiny)
- **Web UI / API：** FastAPI ＋ Streamlit による疎結合・実運用型UI設計
- **DevOps / MLOps：** Dockerによる環境統一および計算リソース（CPU専用ランタイム）の最適化

## 🎯 課題設定 (Problem Statement)
製造業の現場（MIMII Dataset / バルブデータ対象）における背景雑音は -6 dB SNR（信号対雑音比）という極限環境であり、異常時の微細なエアフロー漏れ音や打撃のタイミングのズレは周囲の環境騒音（コンプレッサーやファン）の中に完全に埋没します。
本プロジェクトでは、このノイズ環境下から機械の構造破壊・摩耗兆候をロバストに自動識別できるシステムの確立を目指しました。

## 🧠 アプローチ (ML / Data Science)

### 1. 特徴量設計＆前処理パイプライン
- **音声データ → メルスペクトログラムへのオンザフライ変換（`librosa`）**
  - STFT（短時間フーリエ変換）による時間・周波数特徴抽出。
  - `power_to_db` による対数変換で、異音特有のエネルギー変化を強調。
- **Min-Max正規化の導入（ブレイクスルーの核心）**
  - 対数メルスペクトログラムの最小・最大値を用いて、データを動的に 0 〜 1 の範囲にスケール正規化。モデルの入力層における特徴量の勾配安定化を担保。

### 2. モデル構造と最適化戦略
- **Vision Transformer（ViT-Tiny）の選定**
  従来のCNNが近接ピクセルの局所特徴に偏重するのに対し、ViTはSelf-Attention機構により、スペクトログラム全体のリズムや長周期的な周波数変化（グローバルな調和パターン）を直接学習できるため採用。
- **ハイパーパラメータの固定（事前リサーチに基づく最適化）**
  事前検証に基づき、過学習を最も強力に抑制しパラメータ空間をロバストに最適化できる共通条件として、低学習率（`1e-4`）および重み減衰に優れる `AdamW` オプティマイザを両モデルに均一採用。

## 📊 最終評価指標：完全対照実験 (Evaluation Metrics)
公平かつ厳密な構造比較のため、テストデータ（250件：正常100/異常150）を完全隔離。すべてのマシンID（`id_00, 02, 04, 06`）を混在させ、不均衡比率に基づき「異常の見逃しペナルティ」を **7.7倍** に引き上げた損失関数（`CrossEntropyLoss(weight)`）を同一適用し、5エポック集中訓練にてベンチマークを算出しました。

### 構造優位性の実証データ

| モデルアーキテクチャ（同一の最高条件） | Accuracy（総合精度） | Recall（異常検知率） | F1-score（調和平均） | ROC-AUC（識別力） |
| :--- | :---: | :---: | :---: | :---: |
| 🟦 **ResNet18 (Baseline CNN)** | 74.0% | 62.0% | 0.741 | 0.906 |
| 🔥 **ViT-Tiny (デプロイ済みの提案手法)** | **97.6%** | **96.7%** | **0.980** | **0.997** |

## 🧠 考察：なぜViTがCNNを圧倒したのか？ (Diagnostic Analysis)

### 1. CNNの局所性とドメインシフトの限界
CNN（ResNet18）は、スペクトログラムの「局所的なテクスチャ（特定の周波数帯のノイズパターン）」を捉えることに偏重する特性（近接ピクセルの受容野制限）があります。全マシンの音を混ぜた過酷な環境下では、マシンの個体差や設置位置の違いによってこの局所ノイズの周波数が激しく変化（ドメインシフト）するため、決定境界が曖昧にブレてしまい、Accuracy 74.0% / Recall 62.0% で成長が頭打ちになりました。

### 2. ViTのSelf-Attention構造による完全汎化
対するVision Transformer（ViT）は、**Self-Attention機構**によって画像全体（スペクトログラムの全時間軸・全周波数帯）の相互作用を直接計算します。これにより、AIはマシンの個体差による局所的な雑音に惑わされず、**「バルブが開閉する際の時間的な調和構造」や「故障時に発生する周波数広帯域にわたる位相の破綻」という『ドメインを越えた異常の本質』をシャープに捕捉**することに成功。**Recall 96.7% / ROC-AUC 0.997** という、産業用AIとして非の打ち所がない圧倒的な汎化境界を獲得しました。

### 2. MLOps前線
- **疎結合設計：** モデル・推論ロジック（FastAPI）とUI（Streamlit）を完全に分離。API側への改修のみで、UIを一切破壊せずに97.6%の神モデルへの差し替えを達成。
- **再現性の確保：** Dockerコンテナ技術を採用し、OSレベルのオーディオ依存ライブラリ（`libsndfile1`）を内包。ローカル環境、Colab、Hugging Face間の「環境の差異」を完全撲滅。
- **インフラ最適化：** PyTorchのCPU専用ランタイム（`whl/cpu`）をコンテナ内で指定。無料クラウド枠の限られたCPUリソースでも、ミリ秒単位で動作する超軽量・高速推論を実現。
- **外部連携性：** 推論ロジックのAPI化により、将来的な工場内の他システム（工場内の監視カメラやアラートシステム）との連携が容易。
- **名前空間キーの自動補正：** Lifespan起動時、Colabのチェックポイントから `timm` 固有の接頭辞（`vit.`）の有無を自動検知し、動的に重みのキーをマッピングするロバストなロード機構を実装。

## 📚 学び (What I Learned)
- **音響データにおける特徴量設計の重要性：** 生波形ではなく、適切なパラメータでメルスペクトログラム化し、さらにスケールを揃える「Min-Max正規化」を施す前処理こそがAIの勝敗を分ける最大の命綱であることを痛感。
- **対照実験による説得力の構築：** 単に一つのモデルを過剰に学習させるのではなく、全く同一の条件下で異なるアーキテクチャ（CNN vs Transformer）を競わせることで、モデルが持つ本質的な構造優位性をロジカルに証明するデータサイエンスの王道を学習。
- **MLをプロダクトとして実装する難しさ：** 実験室（Colab）で高い精度を出すこと以上に、API、UI、Dockerに載せてエンドツーエンドでシステムを貫通させ、本番環境へ前処理を完全に同期させる運用の泥臭さと価値を実感。

## 🔮 今後の展望 (Future Work)

本プロジェクトのフェーズ1（MVP）において、完全対照実験を経てViTの圧倒的なドメイン汎化性能を証明しました。今後は、この堅牢なコンテナ・API基盤を土台とし、さらに高度な製品化フェーズ（フェーズ2）へ向けて以下のロードマップを展開します。

### 1. 🔬 モデル・音響信号処理のさらなる高度化
- **8chアレイマイクを活用した空間デノイジングの導入**
  アレイマイク（TAMAGO-03）の空間情報を活かし、目標方向以外の雑音を空間的に遮断する **MVDRビームフォーミング** および **一般化サイドローブキャンセラ（GSC）** をフロントエンドに配置。VAD（活動検出）を用いて工場雑音の共分散行列を動的更新し、入力段階での -6 dB SNRを物理的に改善。
- **位相特性を保持する高次元特徴量（AC-STFT / DeSpaWN）への刷新**
  現行のLog-Melスペクトログラムで破棄されている「位相情報」を救うため、**AC-STFT（非対称複素STFT）** を導入。実数・虚数ベースの振幅と非対称位相シグナルを抽出し、$256 \times 256 \times 2$ の空間テンソルとして入力することで、バルブ開開時の瞬時位相の破綻（うねり）を画像パターンとして捉えます。
- **非対称フォーカルコントラスティブ損失（AFCL）の検証**
  さらに過酷な超極小の少数派異常データ環境を見据え、損失関数を **AFCL** へ移行。判別が容易な大多数の正常サンプルの勾配寄与を自動的に下向減衰させ、境界線上の困難な異常サンプルの損失勾配を大きく増幅させることで、多数派バイアスを構造的に抑圧。
- **過再構成（Over-reconstruction）防止機構を組み込んだエポック制御**
  検証データの「Train-Val 損失ギャップ（閾値 0.006）」を毎エポック厳密に監視するロジックを実装。オートエンコーダやViTが異常信号のノイズパターンまで丸暗記して再構成（過学習）してしまう前に、自動で最適なエポック段階へロールバック・早期終了させるロバストな制御を組み込みます。

### 2. 🏗️ MLOps・システムインフラの拡張
- **リアルタイムストリーミング対応**
  WebRTC等を介し、現場のマイク音声から常時稼働音を連続的に吸い上げ、バックグラウンドスレッドでオンザフライに推論・監視を続けるストリーミングパイプラインへの拡張。
- **モデル監視・ドリフト検知（MLOps強化）**
  機械の経年劣化や工場のサイクル稼働に伴う周囲のノイズ変化（データドリフト）を検知するため、`Evidently AI` 等の監視モジュールを統合。モデルの推論確率の偏りを自動トラッキングし、性能低下検知時に再学習パイプラインを自動トリガーする仕組みの導入。
- **CI/CDパイプラインの自動化**
  GitHub Actionsと連携し、コードやモデル重みの変更時にDockerイメージの自動ビルド、コンテナの脆弱性スキャン、および Hugging Face Spaces への無停止自動ローリングデプロイを実行するフルオートメーションの構築。
- **マルチチャネル・アラートシステム連携**
  異常検知時に、推論の確信度スコア、タイムスタンプ、およびスペクトログラム画像を自動添付し、Slack や LINE Webhook を介して現場の保全エンジニアへ即座に緊急プッシュ通知を送る報知システムの統合。
