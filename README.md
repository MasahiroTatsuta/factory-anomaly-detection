# Factory Anomaly Detection - AI × MLOps × Web統合システム

## 🚀 Summary
本プロジェクトは、工場設備の異常検知を目的としたAI × MLOps × Web統合システムです。
音響不均衡データおよびマシンの個体差（ドメインシフト）という実務上の2大課題をデータサイエンスの力で完全に克服し、実運用に耐えうる高性能な産業用AIシステムを構築しました。

### 成果（最終進化モデル）
- **総合精度（Accuracy）：** **97.6%**（ベースライン比 +57.6% の劇的向上）
- **異常検知率（Recall）：** **96.7%**（多数派に屈したCNNの 0.0% から完全脱出）
- **F1-score / ROC-AUC：** **0.980 / 0.997** という極めて高い識別・汎化性能を達成
- **プロダクト実装：** 本番環境（Hugging Face Spaces）へ前処理パイプラインを完全同期し、リアルタイム推論を実証済

### 特徴
- **アルゴリズム：** 音響データ処理（Min-Max正規化） × Vision Transformer (ViT-Tiny)
- **実験管理：** W&B（Weights & Biases）Sweeps を用いたハイパーパラメータの自動最適化
- **Web UI / API：** FastAPI ＋ Streamlit による疎結合・実運用型UI設計
- **DevOps / MLOps：** Dockerによる環境統一および計算リソース（CPU専用ランタイム）の最適化

## 🎯 課題設定 (Problem Statement)
従来のルールベース監視では、微細な異常検知が難しく、故障検知の遅延や誤検知が多発する課題がありました。
本プロジェクトでは、音響データを2次元の時間・周波数表現に投影し、ディープラーニングを組み合わせることで、ノイズに埋もれた微小な異音パターンを高精度に自動識別することを目指しました。

## 🧠 アプローチ (ML / Data Science)

### 1. 特徴量設計＆前処理パイプライン
- **音声データ → メルスペクトログラムへのオンザフライ変換（`librosa`）**
  - STFT（短時間フーリエ変換）による時間・周波数特徴抽出。
  - `power_to_db` による対数変換で、異音特有のエネルギー変化を強調。
- **Min-Max正規化の導入（★ブレイクスルーの核心）**
  - スペクトログラムの最小・最大値を用いてデータを動的に 0 〜 1 の範囲にスケール正規化。モデルの入力層における特徴量の勾配安定化を担保。

### 2. モデル選定：Vision Transformer（ViT-Tiny）
- **選定理由：** 従来のCNN（畳み込みニューラルネットワーク）が近接ピクセルの局所特徴に偏重するのに対し、ViTはSelf-Attention機構により、スペクトログラム全体のリズムや長周期的な周波数変化（グローバルな調和パターン）を直接学習できるため。

### 3. ハイパーパラメータの自動最適化（W&B Sweeps）
W&Bダッシュボードを用いたランダムサーチにより、ViTと相性の良いオプティマイザおよび学習率の依存関係を可視化。
- **最適パラメーターの特定：** 低学習率（`1e-4`） ＋ 重み減衰に優れる `AdamW` の組み合わせが、過学習を抑制しロスを極限まで下げる最適解であることを実証。

## 🧠 考察 (Diagnostic Analysis)

### 1. なぜ「全ID混在」で覚醒したのか？
フェーズ④までのモデルは `id_00` の音しか知らなかったため、「マイクの位置や個体差による固有ノイズ」を異常検知の手がかりだと脳内で丸暗記（過学習）していました。しかし、全ID（`id_00, 02, 04, 06`）の正常・異常音を一網打尽に聴かせたことで、AIは個体差に伴う雑音を背景情報として無視し、**「バルブという機械が正常に動く時の本質的なリズム」と「故障時の特異な異音パターン」をドメインを越えて見つけ出す「真の汎化性能」** を獲得しました。

### 2. クラスウェイト（7.7倍）との完璧なシナジー
異常の見逃しペナルティを不均衡比率（3691:479）に基づいて **7.7倍** に跳ね上げた損失関数（`CrossEntropyLoss`）を設計。全ID混在によって異常データのバリエーション（329件）が豊かになったことと相まって、「正常の安全地帯に引きこもるよりも、異音の特徴を貪欲に学習した方が損失を効率よく下げられる」とAIが決定境界を正しく再定義。結果として、**Recall 96.7% / ROC-AUC 0.997** という驚異的な大逆転劇へ繋がりました。

## MLOps的観点
- **疎結合設計：** モデル・推論ロジック（FastAPI）とUI（Streamlit）を完全に分離。API側への改修のみで、UIを一切破壊せずに97.6%の神モデルへの差し替えを達成。
- **再現性の確保：** Dockerコンテナ技術を採用し、OSレベルのオーディオ依存ライブラリ（`libsndfile1`）を内包。ローカル環境、Colab、Hugging Face間の「環境の差異」を完全撲滅。
- **インフラ最適化：** PyTorchのCPU専用ランタイム（`whl/cpu`）をコンテナ内で指定。無料クラウド枠の限られたCPUリソースでも、ミリ秒単位で動作する超軽量・高速推論を実現。
- **外部連携性：** 推論ロジックのAPI化により、将来的な工場内の他システム（工場内の監視カメラやアラートシステム）との連携が容易。

## 📚 学び (What I Learned)
- **音響データにおける特徴量設計の重要性：** 生波形ではなく、適切なパラメータでメルスペクトログラム化し、さらにスケールを揃える「Min-Max正規化」を施す前処理こそがAIの勝敗を分ける最大の命綱であることを痛感。
- **不均衡データに対するモデル挙動の理解：** データの偏りによって生じる「多数派クラスへの埋没（CNN）」や「完全な過学習（ViT）」という、実務ならではの洗礼を身をもって体験し、評価指標を多角的に選定する重要性を獲得。
- **モデル精度と推論速度のトレードオフ：** 巨大なリサーチ用モデルではなく、プロダクション環境の制限を見据えた ViT-Tiny の選定およびライブラリ最適化の知見を獲得。
- **MLをプロダクトとして実装する難しさ：** モデル単体のチューニングに埋没せず、早い段階でシステムとして「エンドツーエンドで貫通させる」ことの価値を実感。

## 🔮 今後の展望 (Future Work)

本プロジェクトのフェーズ1（MVP）において、全ID混在学習とクラスウェイトの導入により、不均衡データに対する汎化のブレイクスルーを達成しました。今後は、この堅牢なコンテナ・API基盤を土台とし、さらに高度な製品化フェーズ（フェーズ2）へ向けて以下のロードマップを展開します。

### 1. 🔬 モデル・音響信号処理のさらなる高度化
- **8chアレイマイクを活用した空間デノイジングの導入**
  アレイマイク（TAMAGO-03）の空間情報を活かし、目標方向以外の雑音を空間的に遮断する **MVDRビームフォーミング** および **一般化サイドローブキャンセラ（GSC）** をフロントエンドに配置。VAD（活動検出）を用いて工場雑音の共分散行列を動的更新し、入力段階での -6 dB SNRを物理的に改善。
- **位相特性を保持する高次元特徴量（AC-STFT / DeSpaWN）への刷新**
  現行のLog-Melスペクトログラムで破棄されている「位相情報」を救うため、**AC-STFT（非対称複素STFT）** を導入。実数・虚数ベースの振幅と非対称位相シグナルを抽出し、$256 \times 256 \times 2$ の空間テンソルとして入力することで、バルブ開閉時の瞬時位相の破綻（うねり）を画像パターンとして捉えます。
- **非対称フォーカルコントラスティブ損失（AFCL）の検証**
  さらに過酷な超極小の少数派異常データ環境を見据え、損失関数を **AFCL** へ移行。判別が容易な大多数の正常サンプルの勾配寄与を自動的に下向減衰させ、境界線上の困難な異常サンプルの損失勾配を大きく増幅させることで、多数派バイアスを構造的に抑圧。
- **過再構成（Over-reconstruction）防止機構を組み込んだエポック制御**
  検証データの「Train-Val 損失ギャップ（閾値 0.006）」を毎エポック厳密に監視するロジックを実装。オートエンコーダやViTが異常信号のノイズパターンまで丸暗記して再構成（過学習）してしまう前に、自動で最適なエポック段階へロールバック・早期終了させるロバストな制御を組み込みます。

### 2. 🏗️ MLOps・システムインフラの拡張
- **リアルタイムストリーミング対応**
  WebRTC等を介し、現場のマイク音声から常時稼働音を連続的に吸い上げ、バックグラウンドスレッドでオンザフライに推論・監視を続けるストリーミングパイプラインへの拡張。
- **モデル監視・ドリフト検知（MLOps強化）**
  機械の経年劣化や工場のサイクル稼働に伴う周囲のノイズ変化（データドリフト）を検知するため、`Evidently AI` 等の監視モジュールを統合。モデルの推論確率の偏りを自動トラッキングし、性能低下検知時に再学習パイプラインを自動トリガーする仕組みの導入。
- **CI/CDパイプラインの自動化**
  GitHub Actionsと連携し、コードやモデル重みの変更時にDockerイメージの自動ビルド、コンテナの脆弱性スキャン、および Hugging Face Spaces への無停止自動ローリングデプロイを実行するフルオートメーションの構築。
- **マルチチャネル・アラートシステム連携**
  異常検知時に、推論の確信度スコア、タイムスタンプ、およびスペクトログラム画像を自動添付し、Slack や LINE Webhook を介して現場の保全エンジニアへ即座に緊急プッシュ通知を送る報知システムの統合。
