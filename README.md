# Factory Anomaly Detection - AI × MLOps × Web統合システム

## 🚀 Summary
本プロジェクトは、工場設備の異常検知を目的としたAI × MLOps × Web統合システムです。

### 成果
- **総合精度（Accuracy）：** 57.6%（ベースライン比 +17.6% 改善）
- **異常検知率（Recall）：** **84.0%**（CNN: 0%）
- **F1-score：** 0.704
- **ロバスト性：** 現場の不均衡データおよび複数マシンIDに対する挙動のポテンシャルを確認

### 特徴
- **アルゴリズム：** 音響データ処理 × Vision Transformer (ViT-Tiny)
- **Web UI：** FastAPI ＋ Streamlit による実運用を想定したUI設計
- **DevOps：** Dockerによる再現性のあるポータブルなデプロイ環境

🔗 **本番デモ:** [https://masaroo-factory-anomaly-detection.hf.space/](https://masaroo-factory-anomaly-detection.hf.space/)

## 🎯 課題設定 (Problem Statement)
従来のルールベース監視では、微細な異常検知が難しく、故障検知の遅延や誤検知が発生する課題がありました。
本プロジェクトでは、音響データと深層学習を組み合わせることで、ノイズ環境下でもより高精度な自動異常検知の実現を目指しました。

---

## 🧠 アプローチ (ML / Data Science)

### 特徴量設計
- **音声データ → メルスペクトログラムへ変換（`librosa`）**
  - STFT（短時間フーリエ変換）による時間・周波数特徴抽出
  - `power_to_db` による対数変換で、異音特有のエネルギー変化を強調

### モデル
- **Vision Transformer（ViT-Tiny）**
- **選定理由：**
  - スペクトログラム（画像データ）との高い親和性
  - CNNに比べ、Self-Attention機構により広域パターン（周波数全体の調和や長周期のリズム）を捉えやすいため

### ベースライン比較
公平な比較のため、以下の極限条件下でベンチマークを評価しました：
- **テストデータ：** 250件（正常100 / 異常150）
- **環境：** 複数マシンID混在（`id_00, 02, 04, 06`）
- **学習条件：** 3エポック・ハイパーパラメータ未チューニング（MVP開発フェーズ）

| モデル名 | 正常正解率 (Normal) | 異常正解率 (Abnormal) | 総合正解率 (Accuracy) |
| :--- | :---: | :---: | :---: |
| **ResNet18 (Baseline CNN)** | 100.0% | 0.0% | 40.0% |
| **ViT-Tiny (Proposed)** | 18.0% | **84.0%** | **57.6%** |

## 📊 評価指標 (Evaluation Metrics)
不均衡データにおける真の識別性能を多角的に評価するため、4つの主要指標を用いて検証を行いました。

| 評価指標 | ViT-Tiny (提案手法) | ResNet18 (ベースラインCNN) |
| :--- | :---: | :---: |
| **Accuracy（総合精度）** | **57.6%** | 40.0% |
| **Recall（異常検知率）** | **84.0%** | 0.0% |
| **F1-score（調和平均）** | **0.704** | 0.000 |
| **ROC-AUC（識別能力値）** | 0.491 | **0.672** |

## 🧠 考察 (Diagnostic Analysis)
- **最重要指標の達成：** 工場保全の現場において見落としを防ぐために最も重視される **Recall（異常検知率：84.0%）** において、ViTは優れた能力を発揮しました。
- **多数派バイアスの克服：** CNN（ResNet18）はデータ不均衡（正常3,691件 / 異常479件）の環境下において、最も損失を下げやすい多数派（正常）への過剰適合を起こして機能停止（Recall 0%）したのに対し、ViTは初期学習段階から異常の兆候を貪欲に捉えるポテンシャルを示しました。
- **今後の課題：** 一方でViTのROC-AUC（0.491）は低く、正常データを「異常」と過剰警戒する強いバイアス（偽陽性の多発）が見られるため、出力確率スコアのキャリブレーションや境界線の改善余地が浮き彫りとなりました。

### ⚠️ 評価の制約
本結果はプロトタイプ段階（3エポック・未チューニング）の成果であり、実運用に向けた以下の施策は今後の課題として位置づけています：
- クロスバリデーションによる厳密なモデル評価
- 現場の許容誤検知率に応じた「しきい値（Threshold）の最適化」
- 確率予測の信頼性を高める「確率キャリブレーション」の導入

# MLOps的観点
- **疎結合設計**： モデル・推論ロジック（API）とUI（フロントエンド）を完全に分離。

- **再現性の確保**： Dockerによる「どこでも動く」環境の担保。

- **インフラ最適化**： PyTorchのCPU専用ランタイム（whl/cpu）を指定し、クラウドの無料計算リソース枠に適合した軽量推論を実現。

- **外部連携性**： 推論ロジックのAPI化により、将来的な工場内の他システムとの連携が容易。

# 📚 学び (What I Learned)
- **音響データにおける特徴量設計の重要性**： 生波形ではなく、適切なパラメータでメルスペクトログラム化する前処理こそがAIモデルの命運を分けることを痛感。

- **不均衡データに対するモデル挙動の理解**： データの偏りによって生じる「多数派クラスへの埋没（CNN）」や「過剰適合（ViT）」という、実務ならではの洗礼と評価指標の選び方を学習。

- **モデル精度と推論速度のトレードオフ**： 巨大なリサーチ用モデルではなく、プロダクション環境の制限を見据えた ViT-Tiny の選定およびライブラリ最適化の知見を獲得。

- **MLをプロダクトとして実装する難しさ**： モデル単体のチューニングに埋没せず、早い段階でシステムとして「エンドツーエンドで貫通させる」ことの価値を実感。

## 🔮 今後の展望 (Future Work)

本プロジェクトの初期検証（MVP）において、-6 dB 極低SNR環境およびクラス不均衡（異常比率 11.5%）に起因する「多数派クラスへの偏向」や「過再構成（Over-reconstruction）」といった産業用音響AI特有の重大な技術的課題を特定した。
今後は、現在の堅牢なコンテナ・API基盤（Docker / FastAPI）を土台とし、以下の「データサイエンス」と「MLOpsインフラ」の2軸からシステムを次期フェーズへとスケールアップさせることを目指す。

### 1. 🔬 モデル・音響信号処理の高度化
- **8chアレイマイクを活用した空間デノイジングの導入**
  MIMII Datasetの8チャネル円形マイクロホンアレイ（TAMAGO-03）の空間情報を活かし、目標信号（バルブ正面）以外の雑音を遮断する **MVDRビームフォーミング** および **一般化サイドローブキャンセラ（GSC）** をフロントエンドに配置。VAD（活動検出）を用いて工場雑音の共分散行列を動的更新し、入力段階での -6 dB SNRを物理的に改善する。

- **位相特性を保持する高次元特徴量（AC-STFT / DeSpaWN）への刷新**
  現行のLog-Melスペクトログラムによる高周波の情報圧縮および位相情報の破棄を克服するため、**AC-STFT（非対称複素STFT）** を導入。実数・虚数ベースの振幅情報と非対称位相シグナルを抽出し、256x256x2 の空間テンソルとしてモデルに入力することで、バルブ開閉時の微細な位相破綻を画像パターンとして捉える。また、高時間解像度を持つ学習可能ウェーブレット（DeSpaWN）の併用により、摩擦過渡パルスを背景雑音から数学的に分離する。

- **非対称フォーカルコントラスティブ損失（AFCL）による勾配制御**
  少数派クラスの不均衡勾配問題を解決するため、損失関数を **AFCL（Asymmetric Focal Contrastive Loss）** へ移行。判別が容易な大多数の正常サンプル（イージーネガティブ）の勾配寄与を自動的に下向減衰（ダウンウェイト）させ、決定境界付近の困難な異常サンプルの損失勾配を増幅することで、多数派バイアスを根本から破壊する。

- **過再構成（Over-reconstruction）防止機構を組み込んだエポック制御**
  検証データの「Train-Val 損失ギャップ（閾値 0.006）」を毎エポック厳密に監視するロジックを実装。オートエンコーダやViTが異常信号のノイズパターンまで丸暗記して再構成（過学習）してしまう前に、自動で最適なエポック段階へロールバック・早期終了させるロバストな制御を組み込む。

### 2. 🏗️ MLOps・システムインフラの拡張
- **リアルタイムストリーミング対応**
  WebRTC等を介し、現場のマイク音声から常時稼働音を連続的に吸い上げ、バックグラウンドスレッドでオンザフライに推論・監視を続けるストリーミングパイプラインへの拡張。

- **モデル監視・ドリフト検知（MLOps強化）**
  機械の経年劣化や工場のサイクル稼働に伴う周囲のノイズ変化（データドリフト）を検知するため、`Evidently AI` 等の監視モジュールを統合。モデルの推論確率の偏りを自動トラッキングし、性能低下検知時に再学習パイプラインを自動トリガーする仕組みを導入する。

- **CI/CDパイプラインの自動化**
  GitHub Actionsと連携し、コードやモデル重みの変更時にDockerイメージの自動ビルド、コンテナの脆弱性スキャン、および Hugging Face Spaces への無停止自動ローリングデプロイを実行するフルオートメーションの構築。

- **マルチチャネル・アラートシステム連携**
  AIが異常を検知した際、推論の確信度スコア、発生タイムスタンプ、および異常部位のスペクトログラム画像を自動添付し、Slack や LINE Webhook を介して現場の保全エンジニアへ即座に緊急プッシュ通知を送る報知システムの統合。
